# $100M Offers — Working Skill

Use this skill to **run the book's methods on the user's real offer**. Do not turn the task into a book summary.

## Core operating rules

1. Start with the actual buyer, problem, offer, price, delivery model, proof, and constraints.
2. Work upstream before downstream: market and value come before bonuses, scarcity, urgency, guarantees, and naming.
3. Do not invent customer evidence, conversion rates, capacity limits, deadlines, proof, or guarantees.
4. Scarcity and urgency must be operationally real.
5. Premium pricing follows value, purchasing power, delivery confidence, and healthy fulfillment economics.
6. Guarantees must reflect what the business can control, what the customer must do, fulfillment cost, and measurable outcomes.
7. Prefer specific deliverables and decision logic over promotional adjectives.
8. When information is missing, ask only for what blocks the next important decision. Otherwise label assumptions and continue.
9. Distinguish the book's frameworks from any implementation device added by this skill.
10. Use `cheatsheet.md`, `patterns.md`, and `glossary.md` when deeper routing or terminology is needed.

# MODE 1 — PREP: Build or rebuild an offer

Use when the user has an idea, product, service, package, or weak existing offer.

## Step 1 — Validate the market

Assess four conditions:
- **Massive Pain** — the problem matters enough to motivate action.
- **Purchasing Power** — the buyer can afford the price required for the model to work.
- **Easy to Target** — the buyer can be identified and reached.
- **Growing / Stable Demand** — the market is not structurally collapsing.

Do not try to manufacture demand from nothing. Prefer an existing "starving crowd." Once a viable niche is chosen, test multiple offer versions before blaming the market.

## Step 2 — Define the Dream Outcome

State the customer's desired destination in customer language. Do not confuse the delivery mechanism with the outcome. A course, spreadsheet, workshop, software tool, or consulting call is a vehicle; the buyer wants a result, relief, capability, experience, status, or economic outcome.

## Step 3 — Apply the Value Equation

Increase:
- **Dream Outcome**
- **Perceived Likelihood of Achievement**

Decrease:
- **Time Delay**
- **Effort & Sacrifice**

Look for fast wins, proof, clear milestones, better support, useful tools, reduced waiting, lower complexity, and done-with-you / done-for-you elements where economically sensible.

## Step 4 — Map perceived problems

Walk through the customer's journey before, during, and after using the offer. At each step ask what could make them believe:
- this is not worth it,
- this will not work for me,
- this is too hard/confusing/inconvenient,
- this takes too much time or too long to work.

Do not dismiss an objection because the provider thinks it is irrational. Perceived obstacles affect the buying decision.

## Step 5 — Turn problems into solutions

Reverse each obstacle into a solution. Use the pattern:

**How to [remove obstacle / achieve desired state] with lower time, effort, uncertainty, risk, or cost.**

Also identify the "next problem" created by each solution.

## Step 6 — Generate delivery vehicles

Separate idea generation from evaluation. For each solution, generate materially different delivery options by varying:
- one-to-one / small group / one-to-many,
- DIY / done-with-you / done-for-you,
- in-person / phone / email / text / video / chat,
- live / recorded / written / tool,
- response speed and access,
- personalization,
- the **10x / 1/10th test**: what would you deliver at 10x the price, and what high value could still be delivered at one-tenth the price?

## Step 7 — Trim & Stack

Evaluate each item by customer value and business cost.

Remove first:
1. high-cost / low-value items,
2. low-cost / low-value items.

Keep:
- low-cost / high-value items,
- high-cost / high-value items when the value and price justify them.

For expensive high-value items, look for a lower-cost delivery vehicle that preserves the function. Tools, calculators, templates, checklists, recordings, and systems can have high upfront creation cost but very low marginal fulfillment cost.

## Step 8 — Set pricing logic

Avoid copying competitor prices and moving slightly below them. Diagnose whether the offer is commoditized first.

Check:
- market purchasing power,
- value created for the buyer,
- cost of leaving the problem unsolved,
- delivery confidence and proof,
- direct fulfillment cost and margin,
- the gap between perceived value and price.

Increase value before defaulting to discounting.

## Step 9 — Enhance the offer

Only after the core offer is sound:

### Scarcity
Scarcity is a **quantity constraint**. Use real limits such as total capacity, new-client intake per period, cohort seats, limited units, limited high-touch access, or genuinely limited bonuses.

Never fabricate a cap.

### Urgency
Urgency is a **time constraint**. Use real cohort start dates, seasonal campaigns, scheduled price/bonus changes, or opportunities whose economics genuinely decay with time.

State exactly what changes after the deadline. Never use a fake resetting countdown.

### Bonuses
Use bonuses to solve specific objections and widen the price-to-value gap without weakening the core price.

Strong bonus formats often include:
- checklists,
- calculators,
- templates,
- scripts,
- swipe files,
- tools,
- recorded workshops,
- negotiated partner benefits.

Every bonus should have a benefit-led name, solve a real obstacle, reduce time/effort/risk, include proof where available, and carry a defensible value rather than a fake list price.

### Guarantees
Use the structure:

**If X does not happen within Y time, we will Z.**

Choose among:
- unconditional,
- conditional,
- anti-guarantee,
- implied / performance-based.

Use conditions when customer actions materially affect results. Model the business's cost at risk and ensure measurement is clear.

### Naming — M-A-G-I-C

Use 3–5 components when useful:
- **M** — Make a Magnetic Reason Why
- **A** — Announce Your Avatar
- **G** — Give Them a Goal
- **I** — Indicate a Time Interval
- **C** — Complete With a Container Word

Keep names clear and punchy. Generate several and test; do not pretend a winner can be known in advance.

## PREP output

Return a practical offer plan with:
- Target market / avatar
- Active pain
- Dream outcome
- Core promise
- Value Equation diagnosis
- Problem → solution map
- Core offer stack
- Delivery model
- Price and pricing rationale
- Bonuses and the objections each solves
- Scarcity and operational truth behind it
- Urgency and exact deadline logic
- Guarantee type, conditions, time period, and remedy
- 5–10 candidate names
- Biggest remaining risk
- What to test first

# MODE 2 — GRADE: Audit an existing offer

Use when the user provides a package, landing page, proposal, product description, sales script, promotion, or performance results.

**Diagnose before rewriting.**

Assess:
- **Market** — pain, purchasing power, targetability, growth/stability
- **Differentiation** — can the buyer make an easy price comparison?
- **Price-to-value gap** — is perceived value clearly larger than price?
- **Value Equation** — outcome, likelihood, time delay, effort/sacrifice
- **Problem coverage** — which perceived obstacles remain unsolved?
- **Delivery economics** — is the stack valuable and profitable to fulfill?
- **Bonuses** — do they solve real objections or add filler?
- **Scarcity** — is the quantity limit true?
- **Urgency** — is the deadline true?
- **Guarantee** — does risk reversal fit controllability and cost?
- **Naming** — does the right buyer immediately see relevance and desired result?

For clarity, the skill may use a simple 0–2 audit scale:
- 0 = absent or contradicts the framework
- 1 = present but weak / unclear
- 2 = strong and specific

This 0–2 scale is an implementation aid created for this skill; it is not an official scoring system from the book.

## GRADE output

Return:
1. What is already strong.
2. The 1–3 biggest constraints.
3. The exact changes likely to create the largest value improvement.
4. A revised offer only after the diagnosis.
5. Which framework drove each major recommendation.

# Targeted jobs

If the user asks for one component only, do that job without forcing the full PREP workflow, but check upstream dependencies briefly.

- **Market / niche** → Starving Crowd + four market indicators
- **Pricing** → Commodity Test + price-to-value gap + Value Equation
- **Value** → Value Equation
- **Offer creation** → Dream Outcome + Problems → Solutions + Delivery Vehicles + Trim & Stack
- **Scarcity** → real quantity constraint
- **Urgency** → real time constraint
- **Bonuses** → objection-solving bonus construction
- **Guarantee** → risk reversal and guarantee type
- **Naming** → M-A-G-I-C
- **Quick decision rules** → `cheatsheet.md`
- **Author terminology** → `glossary.md`
- **Routing / named techniques** → `patterns.md`

# Guardrails

- Preserve the user's business reality; do not force the book's gym examples onto unrelated markets.
- Express the customer's outcome before the mechanism.
- Solve perceived obstacles before decorating the offer.
- Show the logic behind price rather than giving a number with no basis.
- Separate the core offer from bonuses.
- State why each bonus exists and which objection it resolves.
- State the operational truth behind every scarcity or urgency mechanism.
- For guarantees, show the trigger, time period, customer conditions, and remedy.
- For names, generate alternatives and recommend testing.
- If a claim could create legal, advertising-platform, financial, health, or regulatory risk, flag that the claim and terms should be validated before publication.
